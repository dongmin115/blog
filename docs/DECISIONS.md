# 결정 기록 (왜 이렇게 정했는지)

대화에서 같이 고민한 내용을 모은 문서예요. `CLAUDE.md`가 요약이고, 이 문서는 이유와 지나온 과정이에요.
새 세션은 여기에 적힌 걸 다시 묻지 말고 기본값으로 삼으세요. 바꾸고 싶은 게 있으면 주인에게 먼저 물어보세요.

## 1. 프로젝트의 목적

- 개인 블로그/일기장. 살면서 느끼고 생각한 것을 기록. 주인은 카카오페이증권 프론트엔드 개발자이고 **React에 익숙**해요. 아이폰을 써요.
- 처음 고민은 "우주 테마로 글을 별로 보일지, 책으로 보일지"였고, 3D 요소가 있으면 더 예쁠 것 같다는 의견이었어요.
- 사용자(읽는 사람)가 **눈이 즐겁고 몰입**되길 원해요. 동시에 **버벅임/프레임 드랍이 전혀 없어야** 해요.
- **모바일에서 글을 쓰고 배포/수정까지** 되는 구조가 필수예요.
- 사진은 **선택적으로** 같이 올려요.
- 카테고리는 1뎁스만이면 단조로우니 **2뎁스 구조**(전체 → 카테고리 → 글)로 하고, 디자인적으로 재미있게 보이길 원해요.
- 읽는 사람이 **로그인 없이** 좋아요를 누르고 조회수가 올라가길 원해요.
- 테마를 바꿔도 **같은 글 소스**를 쓰는 구조를 원해요.

## 2. 호스팅과 공개 범위

- GitHub Pages로 배포. **저장소는 공개**로 해요. (비공개 저장소는 유료 플랜이어야 Pages가 되고, 어차피 사이트는 공개예요.)
- 코드가 공개되는 건 괜찮아요. 비밀 값(토큰, 키)은 절대 저장소에 넣지 않아요. 글쓰기 도구의 토큰은 기기에만 저장해요.
- 저장소 이름은 `blog`예요. (고민 끝에 정했어요: life-log 등 후보가 있었지만 `blog`로 확정.) 배포 주소는 `https://dongmin115.github.io/blog/`.

## 3. 기술 구조

- 처음엔 Astro(+React 섬)를 추천했어요(콘텐츠 중심이라 빠르고, React를 쓸 수 있음). 그런데 개발 환경에서 npm 설치가 막혀 **의존성 없는 Node 빌드**로 시작했어요. 나중에 Astro로 옮겨도 돼요. 글(md)과 테마를 분리한 구조는 유지해요.
- 글은 마크다운 + 머리말(`title`, `date`, `category`, `photo`, `draft`). 글 id는 파일 이름에서 만들고 **바꾸지 않아요**.
- 테마는 플러그인: `src/themes/<id>.js`가 `mount({ el, data, ui, reduce })` → `{ destroy }`. 선택한 테마만 지연 로드해요. WebGL을 못 쓰면 목록 화면으로 대체해요.
- 성능 원칙: 모션이 많은 화면은 캔버스/WebGL로, 오프스크린 레이어 미리 그리기, 가산 합성 글로우 스프라이트, 프레임 시간이 길어지면 해상도 자동 하향, 탭이 숨겨지면 렌더 중지, `prefers-reduced-motion` 존중, 탭/드래그 구분 임계 6px.

## 4. 좋아요/조회수 정책 (구현 전)

- 로그인 없이 익명. giscus(깃허브 로그인)는 마찰이 커서 **채택하지 않았어요**.
- 서버 1대(글 id → likes, views). 후보: Cloudflare Workers + KV/D1(추천), Supabase, Firebase.
- 중복 방지: 기기 localStorage + 서버 쪽 간단한 제한(IP 해시 기반 rate-limit). 완벽한 방지는 목표가 아니에요. 어뷰징이 보이면 그때 강화해요.
- 주인 본인용 통계는 별도 분석 도구(GoatCounter / Plausible / Cloudflare Web Analytics)로.
- 세부 정책(하루 제한, 봇 처리 등)은 **구현하면서 정하기로** 했어요.

## 5. 테마 결정 과정

- **버린 테마**: 지층, 유리병, 책(우주 책), 도서관(3D까지 만들어 봤지만 제외).
- **남긴 테마 2개**: ① **우주(통합)** ② **반딧불 숲**.
- 우주와 별자리가 너무 겹쳤고 둘 다 예뻐서 **통합**했어요: 카테고리 = 별자리(선으로 이어진 별 무리), 글 = 별, 별을 누르면 **입체 행성으로 다가가요**(사진이 있으면 표면에 입히고 고리가 생겨요).
- 2D 캔버스 데모에서는 3D 요소가 부족해서, 우주는 Three.js로 진짜 3D로 만들었어요(`src/themes/space.js`). 반딧불은 원근 투영으로 이미 입체감이 있어서 **Three.js로 바꾸지 않아요**(가볍게 유지).
- 모든 테마는 **가로 스크롤 없이 한 화면 너비**에 맞아야 해요. 사용자가 이걸 분명히 지적했어요.

### 반딧불 숲에서 겪은 시행착오 (같은 실수 반복 금지)

- 개념: 물 위에서 보트를 타고 반딧불 나무 숲으로 **y축(깊이)으로 들어가요**. 들어갈수록 나무가 무성하게 나타나요.
- 스크롤: **아래로 끌면 앞으로** 가요(처음엔 반대였고 사용자가 고치라고 했어요).
- 카테고리 선택: 처음엔 나무에 이름표를 달았는데 **어디를 눌러야 할지 몰라서** 실패했어요. 이정표로 바꿨어요.
- 이정표 1차(한 화면에 판 4개 모아둠)는 "너무 구리고 너무 커요". 2차(강이 4갈래로 갈라지는 갈림길)는 "2뎁스와 디자인 차이가 너무 나고 점선/스포트라이트가 **밤티**나요". 결론: **원래 2뎁스 풍경(호수 같은 물 + 큰 나무 줄기)이 좋고**, 1뎁스도 길과 물을 구분하지 말고 **나무 사이가 길인 것처럼** 해요.
- 최종: 1뎁스도 2뎁스처럼 **깊이로 들어가며** 이정표가 깊이마다 하나씩 나타나요. 이정표는 나무판이 안쪽 위로 기울어 **나무 사이를 가리켜요**(정면일 필요 없음). **카테고리별 색은 쓰지 않아요**(알록달록 금지, 단색 나무색 + 호박빛 등불).
- 이정표는 "그냥 도형 같다"는 피드백을 받아서 **질감**(나뭇결, 옹이, 못, 이끼, 들쭉날쭉한 가장자리, 줄에 매단 이름표, 위에 앉은 등불)을 넣었어요. 글씨체는 붓글씨 느낌의 `East Sea Dokdo`.
- 길 위에 점선, 스포트라이트 같은 빛, 길과 물을 따로 칠하는 건 **금지**예요.
- 가까이 지나가는 이정표가 화면을 덮지 않게 크기 상한과 페이드를 둬요.
- 원본 코드: `reference/forest-demo.html`.

## 7. 글쓰기(모바일) 계획

- 아이폰에서 글 작성 + 사진 첨부 + 게시/수정. 방식: PWA 글쓰기 화면이 **GitHub API로 `content/posts/*.md`와 사진을 커밋**하면 Actions가 배포해요.
- 인증: 개인 액세스 토큰(최소 권한, `blog` 저장소의 contents 쓰기만)을 기기 저장소에 보관. 서버에 토큰을 두지 않아요.
- 사진: 올릴 때 긴 변 1600px, WebP로 줄여요.
- 초안: `draft: true`로 커밋하면 사이트에 안 보여요.

## 8. 환경에서 겪은 일 (참고)

- 이 프로젝트는 처음 클라우드 세션에서 시작했어요. 데모는 Artifact 미리보기로 만들었고, 실제 렌더링은 확인하지 못한 채 코드만 점검한 적이 많아요. **Three.js 화면은 한 번도 실제 렌더링을 못 봤어요.** 로컬에서 처음 확인되니, 어색한 부분(행성 크기, 카메라 거리, 조명 밝기)이 나오면 바로 조정해야 해요.
- 주인의 로컬 터미널에서 `claude`가 `permission denied`로 안 열린 적이 있어요(PATH의 `claude`가 폴더이거나 실행 권한이 없는 경우). `type -a claude`로 확인하면 돼요.
